# noob-debug

**面向编程小白的 AI Bug 修复技能。你描述现象，AI 负责调查你没想到的边界，并用证据说明修复是否有效。**

它提供从接手问题、核对环境、寻找根因，到修复、回归验证和交付的工作方法。核心流程保持集中，16 份参考文档按问题类型读取，避免每次修小问题都执行全项目审计。

## 怎么用

安装后，可以这样对支持此技能的 AI 编程助手说：

```text
使用 $noob-debug 帮我修这个问题：

我看见的现象：……
我希望的结果：……
我的操作步骤/截图/报错：……

我不懂代码。请自行调查相关环境、执行链路和边界，
完成修复与验证，并用我能理解的话说明结果。
```

不知道的内容可以不填。技能要求 AI 先调查能自行查明的事实，只在真正影响业务行为、目标或权限时向你提问。

如果你想减少重复，可以只说“使用 noob-debug 修复这个 Bug”，再描述问题。具体调用和自动发现方式取决于使用的助手；不要把某个助手的行为当成所有工具都支持。

## 安装

本仓库根目录就是一个完整技能目录，名称应保留为 `noob-debug`。

在 Codex 中，将下载或克隆的整个目录放到技能目录，默认是 `~/.codex/skills/noob-debug/`；如果已设置 `CODEX_HOME`，则使用该目录下的 `skills/noob-debug/`。确认该目录内直接包含 `SKILL.md`、`references/` 与 `agents/`，避免多套一层文件夹。已有同名技能时先比较和备份，不直接覆盖个人修改。

这是一份 Markdown 指令技能，本身不运行程序、不携带凭证，也不需要安装运行依赖。真正修复项目时，AI 使用宿主提供的工具和项目已有环境。对于其他支持技能的助手，遵循其技能目录约定；不识别技能格式时，也可以让它读取 `SKILL.md` 并根据其中链接读取参考文件。

## 它要求 AI 主动做什么

- 确认修的是你实际运行的项目、分支、版本、账号和环境。
- 把“卡住了”“一直跳”“保存不了”转成能实际检查的行为。
- 沿真实执行链路找原因，区分事实、推测和验证结果。
- 从状态生命周期、数据身份、事件顺序、部分失败和调用契约推导边界。
- 修复相关机制，保留正常行为，避免无关重构和特殊判断堆叠。
- 尽可能证明关键回归在修复前失败、修复后通过。
- 区分单元测试、模拟数据、模拟器、真机和真实服务验证。
- 告诉你交付的是代码、安装包还是已运行的新版本，以及还缺什么。

## 使用边界

详细不等于无条件穷尽。技能要求按当前代码与现象选择相关检查，既不能漏掉有证据的重要风险，也不能把每个 Bug 扩大成重构、安全审计或全部平台测试。

技能不能弥补助手缺失的工具、设备、账号或真实业务信息，也不能保证一次找出所有问题。它要求明确说明这些限制，不用漂亮的完成报告代替实际验证。

技能不会自动授予部署、合并、生产数据修改或第三方发信权限；继续遵循用户在当前任务中的授权。它也不会指定模型供应商或改变用户的模型偏好。

维护时应根据实际试用发现改进规则，保持参考可按需读取，避免为单个案例不断追加普遍禁令。
