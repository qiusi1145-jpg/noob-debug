# 文件、平台、脚本与进程

## 路径不是普通字符串

核对相对路径的基准、当前工作目录、用户目录、容器挂载和实际输出位置。同名文件可能属于不同目录或不同磁盘。

根据支持环境检查空格、中文、表情、引号、长路径、大小写差异、保留名称、尾部空格/点、网络盘、只读目录和同步目录。不同系统的大小写与路径分隔规则不同。

涉及删除、覆盖、递归扫描、移动或解压时，验证解析后的目标位于预期范围，考虑符号链接、重解析点、路径穿越和根目录边界。不要把未经验证的拼接路径直接用于破坏性操作。

## 读写与原子性

文件可能为空、缺失、损坏、被锁定、正在增长或在检查后改变。检查“存在”不能保证下一步能读写，也不能证明内容完整。

写入期间磁盘可能满、进程退出或权限变化。按平台和项目要求使用临时文件及适当替换策略；核对跨文件系统移动不一定原子。失败不能留下被当成成功结果的半成品。

并发任务的临时文件名与输出名应避免碰撞。覆盖策略应明确，不擅自覆盖用户源文件。确认写入完成后再报告可用，必要时重新读取或校验。

## 编码与内容类型

检查 UTF-8/本地编码、BOM、换行、末尾换行、二进制误按文本读取、CSV 分隔与引号规则，以及分块读取跨字符。扩展名与声明的 MIME 类型不能单独证明实际格式。

导入导出检查字段顺序、空字段、转义、多行、公式或可执行内容在目标应用中的解释。不要把导出成功等同于目标应用能正常打开。

压缩包检查路径、解压后大小和文件数量，避免写到目标之外或耗尽资源；只在涉及不可信导入时展开这些边界。

## 命令与子进程

优先用参数数组与标准输入传递内容，避免把文件名、用户输入或 JSON 当作已转义的 shell 代码。不同 shell 的引号、变量展开和命令替换规则不能混用。

明确可执行文件版本、工作目录、环境、退出码、标准输出与错误输出。命令返回 0 不一定证明业务结果正确；有输出也不代表进程已完成。

长输出可能阻塞管道，子进程超时可能留下后代进程。取消与清理应只处理本任务拥有的资源，不能按进程名批量终止用户应用。

脚本处理多个文件时检查单项失败如何传播、是否返回非零、是否继续处理其余项，以及重跑会不会重复写入。不要悄悄忽略失败项。

## 平台与运行方式

区分本机与远端、宿主机与容器、管理员与普通用户、交互 shell 与服务进程、开发运行与打包应用的环境。PATH、代理、区域设置、字体、动态库和权限可能不同。

跨系统脚本需要核对真实支持平台，不为了假想兼容添加所有分支。Windows 文件占用、Unix 权限、容器 UID 和不同架构上的原生依赖都应由实际证据触发调查。

## 验证重点

使用隔离样本目录验证正常、特殊文件名、失败和重跑；检查实际路径和文件内容。删除测试只作用于明确归属的临时目录。打开生成产物或用独立读取方式检查，不只检查文件存在和大小非零。
