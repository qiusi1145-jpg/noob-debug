# 界面、交互与生命周期

## 判定依据

检查用户正在完成的动作、实际看到的内容和操作连续性。截图相似、组件存在或列表索引不变都不能单独证明体验正确。优先在真实组件与实际布局中验证，独立演示页只能证明其自己的实现。

## 身份与展开状态

- 列表 key、选中项、展开项是否绑定业务身份，还是绑定会变化的位置、整个内容集合或对象引用。
- 追加、前插、排序、过滤、分页、删除和快照替换后，同一逻辑项是否仍对应原状态。
- 单条变分组、组拆分合并、审批插入、占位项变实际项时，状态是否能够按产品意图迁移。
- 虚拟列表滚出可见区后组件可能销毁。需要保留的状态应在合适的上层保存，返回时恢复；切换会话或用户时又必须隔离。
- 展开、选中、编辑草稿和滚动位置不一定具有相同生命周期，不要为了方便一起全局缓存。

## 滚动与动态布局

区分自动跟随最新内容、用户主动阅读、程序恢复位置、动画滚动和拖动惯性。说明每种模式何时进入、何时退出，不能只依赖某一帧“恰好位于底部”判断用户意图。

测量用户正在读的稳定内容：某条消息、某个段落或具体文字行的屏幕坐标。列表 index/offset 不变时，内部增高仍会导致文字移动；index 改变也可能只是前插数据而视觉位置未变。

检查流式追加、图片解码、字体加载、Markdown 重排、代码区展开、键盘弹出、窗口缩放和屏幕旋转中实际涉及的布局变化。只锁定父容器边缘，可能无法保住其中的文字。

多个子组件直接补偿滚动容易冲突。必要时统一协调；观察布局与修改滚动分离，避免布局回调触发循环。用户拖动、惯性滚动或选中文字期间应避免争抢控制权。达到列表边界无法补偿时要收敛，不能无限反复校正。

回底按钮、发送消息、用户手动回到底部等恢复路径分别验证。检查滚动按钮本身是否会遮挡内容或失去可点击性。

## 输入、焦点与选择

- 受控输入更新是否覆盖用户尚未提交的文本；异步自动保存旧响应是否替换新输入。
- 中文输入法组合阶段是否被提前验证、提交或格式化；粘贴、多行、表情、组合字符是否保留。
- 焦点是否因重建、列表重排或弹窗消失而丢失；键盘提交是否与点击按钮重复触发。
- 更新内容时光标、选区、代码预览内部横纵滚动是否重置。主列表位置正确不能证明内部编辑器位置正确。
- 验证失败后输入是否保留，错误是否指向正确字段，修正后是否能再次提交。

## 操作顺序与反馈

快速双击、连续展开收起、进行中返回、取消后立刻重试、多窗口操作，只选择与当前状态处理相关的情况。

按钮禁用可以改善体验，但无法替代服务端防重复。加载提示应在成功、失败、取消和过期结果路径中正确结束；成功提示需对应真实完成阶段。

乐观更新失败时应恢复正确状态，不能撤销用户在此期间产生的新修改。删除与撤销、重试与返回不能依赖已经销毁的界面对象。

## 设备与可访问性

涉及布局时检查实际支持范围内的窄窗口、字体放大、缩放、长翻译文本、键盘遮挡和安全区域；涉及操作入口时检查键盘、触摸与辅助技术是否仍能触发。

原生应用考虑前后台、系统回收、旋转、权限弹窗和资源重建；网页考虑路由切换、刷新、浏览器前进后退、多标签页和旧缓存。只检查项目实际支持的生命周期。

没有原设备时使用合理替代环境并说明差异。模拟器通过不能证明特定厂商系统通过。

## 合适的验证

测量真实可见内容坐标，使用有依据的容差；确认测量内容确实在视口内。用真实操作触发状态变化，必要时控制流式事件顺序。既检查持续更新时的过程，也检查结束后仍能继续操作。

避免只断言“节点存在”“没有调用某函数”“列表没有到 index 0”；这些可能遗漏用户感受到的漂移、闪烁或状态丢失。
