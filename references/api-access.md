# 接口契约与访问边界

按当前问题实际涉及的接口、数据和权限检查，不把普通 Bug 修复升级为全站安全审计。

## 契约与兼容

确认方法、路径、参数、必填项、类型、默认值、单位、时间格式、分页方式、状态码和业务错误含义。请求返回 HTTP 200 不一定代表业务成功。

检查客户端与服务端是否使用同一版本协议；滚动部署时新旧版本可能并存。新增字段、缺失字段、未知枚举值和错误响应应按实际契约处理，不能随意填默认值掩盖不兼容。

对接第三方时优先查看实际版本的官方资料与脱敏响应，核对超时、速率限制、幂等和分页承诺。不凭记忆假定某个 SDK 或服务支持某项行为。

修改共享接口前搜索调用方。区分向后兼容的扩展与会改变含义的行为；必要时更新相关调用方、契约测试与文档。

## 身份、权限与隔离

区分“是谁”和“是否有权操作这个对象”。前端隐藏按钮只能改善界面，服务端或实际执行层仍需做必要授权。

核对对象归属、用户/租户范围、读写权限和账号切换后的状态。不要只验证自己的管理员账号成功，也要在相关场景验证普通权限或拒绝路径。

刷新凭证时考虑并发请求、旧凭证、登出和再次登录。旧账号的请求、缓存、订阅和后台任务不得影响新账号。

如果问题是没有权限，不能通过换成高权限账号、取消对象范围限制或暴露资源来绕过。确需权限变更时解释具体缺口并遵循授权要求。

## 输入与信任边界

解析、验证、规范化和转义应发生在正确层。外部 JSON、文件、网页、日志和模型输出不可信；“来自系统内部”也不意味着其中所有字段可信。

涉及 SQL、shell、HTML、文件路径或 URL 时检查对应上下文的参数化/转义，不能把一种编码当成适用于所有目标。校验与实际使用应针对同一含义，留意二次解码和规范化差异。

仅在相关功能涉及外部 URL 抓取、上传、富文本或回调时，检查地址范围、文件类型、执行内容和跨域/请求来源规则。修复不应关闭 TLS 校验、鉴权、CSRF 防护或来源限制来消除错误。

## 错误与信息暴露

给用户可行动的错误，内部保留必要定位信息。日志、异常页、请求 URL 和公开工单不能包含密钥、会话令牌、完整个人数据或数据库连接串。

不要把所有失败都变成空结果或成功状态。区分不存在、未授权、暂时不可用、输入不合法和部分成功，按产品契约决定哪些信息可以对外显示。

## 外部影响与测试

测试发送邮件、通知、支付、计费 API 或第三方写入前，确认使用的是测试环境和合适目标。已有授权在范围内有效，不能因为技能存在就假定允许影响真实用户。

外部操作结果不明时先查询状态。重试策略见 [异步与网络](async-network.md)。

验证正常路径、拒绝路径、账号切换和相关兼容路径，检查实际返回数据与副作用归属。不能只测“获得 200”或“按钮显示”。
